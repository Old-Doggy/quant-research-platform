### 2.1 数据与真实样本

- A 股覆盖按沪、深、北三个市场分别列出存续、新上市、退出证券和历史有效期。全市场验收分母来自有版本的主表及交易状态，不能拿本次下载到的证券数作分母。若北交所等覆盖不足，记录具体缺口，不能把缩小范围后的成功称为全市场通过。
- 首轮历史回填规划采用 **2021-01-01 至验收时最近已完整交易日**；已有实验仍保留各自原区间。此日期是本轮新增采集的规划边界，不表示已有五年数据，也不表示无须更早的上市和事件元信息。B01 若发现既有承诺要求更早区间，登记并沿用更早要求；不得为通过验收缩短既定范围。此后不因“还能更长”继续扩历史。
- 定向真实证据集至少覆盖：普通股/科创或创业板/北交所、新上市、已退出、现金分红、送转、停复牌、涨跌停限制；财报公告前后及真实修订；成分调入/调出及行业变化；不同规则 ETF；转债转股价变化、赎回/回售或到期退出。案例可复用同一证券，但每种情况要有来源、日期和预期判断。找不到证据就保留待验收，不编造案例。
- 全市场行数/缺口检查与定向案例核对都必须做，抽样不能替代全量覆盖核验。免费行情目前最多 20 只沪深证券、最多一年，仅为浏览能力；其通过不关闭完整 M2。
- 备用能力按 `真实上游 × 数据集 × 市场 × 字段 × 时段` 登记。新浪、腾讯、BaoStock 独立记录；AKShare 包装不是额外独立来源。东方财富当前受限，只保留有限探测结论，不循环探测。
- Tushare 无已验证凭据；历史行业/成分、财务 PIT、公司行为、ETF/转债事件的完整权限与授权均需核验。不能以当天抓取的旧报告补造过去的可得时间，也不能将月末成分权重倒填整个历史月份。

### 2.2 一致性和视觉标准

| 项目 | 本轮固定标准 |
|---|---|
| 数据可追溯 | 原始批次、规范化版本、快照、查询、实验、图表能连回同一来源；缺值/未知不变为零 |
| 数量、金额、收益 | 股/份/张和面值分开；数量按品种精度精确核对；现金按账本声明的舍入规则核到分；独立计算的收益/权重误差绝对与相对容差均为 `1e-10`；逐点保存/恢复及图/表/CSV按现有 `1e-12` 合同核对，不放宽旧合同 |
| 跨源差异 | 按公布精度、最小报价单位与单位换算判断，报告差异原因；不是所有列统一套百分比容差。冲突不取均值，不自动替换整个 bar |
| 图形主次 | 一个主问题对应一个主图；其余用视图切换或小图。K线/量/默认指标、净值/回撤、财务趋势、暴露/贡献、溢价散点各用适合的图形，不堆满首屏 |
| 字体与布局 | 使用现有主题统一变量；正文目标 16px，轴/图例/悬停关键文字不低于 14px；四宽度 1024/1280/1440/1920；无关键文字截断、覆盖、页面溢出。表格可在自身区域横向滚动 |
| 信息表达 | 名称、日期、单位、口径就近可见；数据说明用低强调链接/详情入口。无重复防御性长文，无空泛模型说明，无把价格走势称为总回报 |
| 必需交互 | 时间图有悬停、缩放/平移、重置；比较图可切系列；可选择图能联动详情且有选择器/表格的键盘等价操作；图/表/CSV同源。只读选择器手形且无可见插入符，真实搜索/输入仍可打字 |
| 图形诚实性 | 缺口不连成假连续线；零、负数和不完整年保留；采样保留极值与缺口，下载全量；财务流量与存量分开；未通过研究的作品状态保留 |

现有 64 个渲染入口是扫描结果，不是 64 张图。B01 登记可达路由及变体框架；B30 在功能冻结版本上一次确定最终可达清单。不可达旧入口须记录原因并清理或隔离，不能靠忽略难验的图缩小清单。

### 2.3 性能与日更预算

以下是验收目标，不是已有实测。已有组合切页 p95 约 494ms，尚未达到 300ms。固定同机、同依赖、同样本和浏览器版本；每类操作至少 21 次，首调用单列，余下 20 次计算 p50/p95，保留全部原始耗时。冷启动另起进程，不冒充磁盘缓存已清空。

| 测量 | 固定目标/方法 |
|---|---|
| 热查询 | 10、100、全池三档列/日期裁剪，p95 < 1 秒；同时保留百万行合成基准和真实覆盖数据记录 |
| 主要交互 | 已有结果切视图、选日期/证券到目标内容实际绘制 p95 < 300ms；不能用旧图存在或按钮变色作为完成。后台长计算单列，不混为切页 |
| 新增规划预算 | 应用进程冷启动到首页可用 p95 ≤ 10 秒；100 证券×3 年日频参考策略 p95 ≤ 10 秒；100MiB 标准备份恢复 p95 ≤ 30 秒。B01 固定样本和依赖后执行，不用换小样本通过 |
| 内存与预算 | 上述参考任务 Python 进程峰值 ≤ 2GiB；同一浏览器 50 次重复切页后，应用进程与浏览器分别比较后10次/前10次稳定占用中位数，增长各 ≤ 100MiB；查询遵守现有行数/结果预算，超限明确拒绝；长任务支持取消 |
| 日更 | 规划上海时间 18:30 首次、22:30 补跑，次交易日 09:00 前核定上一日是否完整。B01 依各源实际更新说明确定分类窗口并锁定；晚到字段保留“未完整”，不能伪造准点全量 |

新增预算用于让收尾有判断标准；若两轮剖析修复后仍不达标，记录未通过和原因，不自行放宽目标或重写整套前端。网络更新另记延迟、重试、字段缺口，不将网络波动隐含进本地性能承诺。

## 5. 防止无限延长的执行约束

1. **先收敛欠项。** 每包开始先读已有证据，相同合同/实现未变且已通过的检查直接复用；只补缺口。禁止把所有页面再设计一遍、重做全网调研或新增框架。
2. **一个切片一个交付。** 依次执行“失败/真值样本→最小修改→受影响验证→实际入口核对→复核差异→提交→更新状态”。正文/样式的低风险小改只做必要视觉核对，不为凑数量新增测试。
3. **故障修复有上限。** 初验失败后最多两轮针对同一根因的修复复验，每轮记诊断、改动、证据。仍失败则本包标未通过，停止相关扩展；可继续独立工作。恢复该包须有新的具体证据/外部条件或用户明确调整目标，不能改编号重置轮次。
4. **来源探测有上限。** 每个“上游×接口×权限配置版本”最多两次独立探测批次；每批遵守官方限频，暂时网络错误最多三次有退避的请求，权限错误不盲重试。两批无新证据就登记未启用/等待条件；获得新权限或已确认修复再开。禁止读取或打印token到记录。
5. **验证有边界。** 切片只跑受影响检查；每2–3包核对链路；各阶段候选和最终发布候选各一次全量回归。相同候选没有新变化/失败/疑点，不重复全量。最终候选被修复后只重验受影响范围及依赖，重新冻结候选；涉及核心合同才重跑全量。
6. **图形验收通过即冻结。** 以2.2清单为准。M5功能冻结后只修数值、数据口径、交互、可读性、布局缺陷。新的配色偏好、动画、装饰不阻塞本轮；记入下一版本，不能以“还不够高级”无限返工。
7. **问题分级而不隐藏。** P0=数据污染/泄露；P1=收益、时点、单位、规则、恢复错误或核心功能不可用；P2=本计划必需可读性/交互/响应式/性能不合格；以上均阻止相关阶段关闭和最终发布。P3=已满足标准后的非必要装饰偏好，单列下一版且不算本轮缺项。不可通过降级问题严重程度绕过验收。
8. **每个工作段要有产物。** 单切片以约2小时聚焦工作为拆分参考；到段末必须交付具体提交/证据，或诊断及阻碍。一个工作包连续两个工作段无可验证进展，暂停该包做范围内拆分/定位报告，不继续盲改。该时间是拆分规则，不承诺所有功能两小时完成。
9. **外部等待不占用无限工作。** 缺权限/真实交易日/声明系统环境时登记所需条件，继续独立任务。不得购买数据、激活常驻系统任务或改公开授权范围来绕过等待；这些操作按实际授权处理，不为普通本地开发逐步索要批准。
10. **范围变更留痕。** 本轮36包和原44项是基准，不按测试数量估百分比；新增需求进入另表。任何减少原范围、放宽验收或更换总体前端架构都必须说明影响，不能自行视为原计划完成。

## 6. 进度报告格式与工作量安排

每个交付切片结束、检查点结束、出现外部阻碍或达到停止条件时，更新 [状态入口](../status-v2.md) 和 [验收记录](../acceptance-v2.md)。日常面向用户报告用以下固定格式，避免只有“持续优化中”：

```text
候选版本：提交ID / 日期
当前阶段、工作包、切片：M? / B??.?；状态：待执行/实施中/待验收/通过/等待外部条件/未通过

```

总进度展示36包各状态数量及原T项覆盖，不把“计划已写”当“包已通过”；父包需所有子切片通过。真实数据未到位时，明确写“机制通过、真实验收等待”，父包不标通过。

以下是剩余工作规划区间，按一个执行者的有效工程人日（约6小时聚焦工作）估算，**不是实测工期或自然日承诺**；不含采购/权限等待，不含真实交易日必须经过的时间：
