# 每日数据更新

当前开发版先提供小范围免费原始日线闭环：BaoStock证券资料/沪深日历、BaoStock与新浪行情、独立核对和版本发布。每次1至20只沪深A股，最长一年；该快照供行情浏览，公司行为、财务时点与历史交易制度未验证时仍不能回测。Tushare下载与参考适配器已实现，账户权限待本机token验证。按精简计划，全市场多年扩展延期。

先安装可选采集组件：`python -m pip install -r requirements-providers.txt`。本机请求文件不要提交到GitHub，例如：

```json
{
  "root": "D:/quant-local/market-service",
  "symbols": ["600000.SH"],
  "start": "2025-01-01",
  "end": "2025-01-06",
  "dataset_id": "free-a-daily"
}
```

运行`python -m portfolio_app.update_cli --request 请求文件.json --result 结果文件.json`。进程独立于浏览器，原始批次、任务状态和快照保存在root目录。结果文件只记录状态/缺项/版本；失败不替换当前快照。缺日、停牌或两源差异进入待核对，不能用另一份复权行情顶替。

同一数据目录的免费刷新由进程锁保护；页面与命令行同时启动时，后启动者返回`update_busy`，不同时改写任务。页面发起的请求记录在`launches`中，重开页面可以恢复查看；子进程持有运行锁，意外退出且没有结果时显示“任务中断”，不会永久等待。启动保留15秒宽限期。该机制检测进程退出，不检测仍存活进程中的死锁；采集子进程另有超时保护。

进入行情分片阶段后，主表、日历和分片任务固定到带校验的`refresh-plans`。更新页显示各来源/证券状态；“只重试未完成分片”复用原计划及成功批次，不重抓成功证券。命令行重试可用只含`root`和`resume_plan`的请求JSON，计划ID见上次结果。retry_wait遵守原退避时间，未到期不会发请求。未生成计划前的主表/日历失败需重新启动更新。重新点击“更新数据”是一次新采集，不能以旧成功任务替代对来源修订的检查；同一已成功计划重跑则不产生重复版本。

更新窗口采用上海时区：08:30检查主表及补抓，09:25后检查因子/约束，18:30抓日线，21:30核对晚间事件。这些是建议窗口，不是数据到齐承诺。当前单次入口执行明确日期范围；自动模式`daily_raw`只覆盖原始日线，其他数据类尚未接入调度。

自动模式请求包含`root`、`symbols`、`start`、`schedule: "daily_raw"`，不含固定`end`。18:30上海时间之后请求至当日，此前请求至昨日；交易日仍以真实日历筛选。更新成功日期记录在带校验的`schedules`中，同一天不重复采集；失败不记完成，保留计划后复用失败片。正常持续运行超过一年后，请求起点滚动至截止日前366天，调度身份仍用原始起点；结果分别返回`requested_start`与`effective_start`，历史快照不删除。首次跨度过长或休眠超过滚动范围导致未覆盖历史时，会要求分段补抓并设置新起点，不默默丢掉缺口。当前不将多个年度合并成一个查询快照。节假日重核窗口，不伪造新的交易日。

Windows模板`scripts/register_update_task.ps1`默认仅说明配置，传`-Enable`才注册每小时唤醒一次的任务，由程序按上海时区决定截止日期，避免主机夏令时改变业务窗口。此轮未执行启用。模板使用StartWhenAvailable和IgnoreNew，错过时可启动、同任务不重叠；电脑休眠期间不能采集，开机后按原起点补抓。停止可在任务计划程序禁用，或使用模板的-Remove。模板也能运行固定日期请求，但要自动推进日期须使用上面的schedule模式。尚未在本机系统任务中完成跨休眠持续实测。

不要把已发布行情快照当作完整研究数据包。旧版可按snapshot_id读取；回退只改变当前指针，不删旧文件。批次与快照目前不自动清理，避免删掉历史引用；容量保留与恢复按M5统一验收。
